# 8大异议处理完整话术

> 客户说不，才是销售的开始。每个"不"背后都有一个真实原因。

---

## 异议1："太贵了"

### 心理分析

90%的情况**不是真觉得贵，是觉得不值**。剩下10%是真没预算或预算不够。

客户说"太贵了"的真实含义可能是：
- "我还没感受到值这个价" → 价值塑造不够
- "我不知道这个价格合不合理" → 缺乏参照物
- "我想试试你的底线" → 谈判策略
- "我确实买不起" → 真预算问题

### 处理步骤

```
步骤1：共情（不要反驳）
"我理解，确实是一笔投入"

步骤2：拆解（把大数字变小）
"您算一下，用3年，均摊到每天才XX元"
"一个月才XX元，比一杯咖啡还便宜"

步骤3：对比（给参照物）
"跟[竞品]比，我们贵10%，但效果好50%"
"跟[不解决的损失]比，这个投入3个月就回来了"

步骤4：案例（用数据说话）
"XX公司用了之后，3个月就回本了"
"XX公司一年省了XX万"

步骤5：选项（给台阶）
"如果预算有限，可以先做基础版，XX万起步"
"我们可以分期/按模块付费"
```

### 万能回复模板

```
"王总，贵不贵要看跟什么比。
跟[竞品]比，我们贵10%，但效果好50%。
跟[不解决的损失]比，这个投入3个月就回来了。
如果预算有压力，我们可以先做核心模块，XX元起步。"
```

### 进阶：不同情况不同应对

```
情况A：客户从不讨价还价 → 真觉得不值
→ 重点做价值塑造，用案例和数据

情况B：客户讨价还价很厉害 → 觉得值，但想更便宜
→ 用条件交换（签长约/预付/加模块换折扣）

情况C：客户直接说买不起 → 真预算问题
→ 推荐基础版/分期/等预算周期

情况D：客户拿竞品价格比 → 试探底线
→ 打价值战，不打价格战
```

## 异议2："考虑一下"

### 心理分析

"考虑一下"99%是借口。真实原因可能是：
- 不想直接拒绝你（中国人的面子文化）
- 有顾虑但不好意思说
- 需要跟别人商量
- 还没被说服

### 处理方式

```
"没问题，考虑是应该的。
不过我想确认一下，您主要是在考虑哪方面？
是价格、效果、还是时间安排？
这样我也能帮您更好地分析一下"

→ 把模糊的"考虑"变成具体的问题
→ 然后逐个解决

如果客户说"都还好，就是想再想想"：
"理解。那我给您做个方案对比表，
把选我们和不选的利弊列清楚，
您看着更直观。什么时候方便我发您？"
```

### 如果客户真的需要时间

```
"没问题！那我X天后联系您，
您先看看资料，有问题随时找我。
对了，您大概什么时候能给我一个反馈？
我到时候安排一下时间"

→ 锁定一个具体的跟进时间点
→ 不要说"您考虑好了联系我"（客户永远不会主动联系你）
```

## 异议3："不需要"

### 心理分析

"不需要"通常意味着**还没意识到自己需要**。不是真的不需要，是没看到痛点。

### 处理方式

```
"理解，很多客户一开始也这么说。
但我好奇的是，你们现在[相关业务]是怎么做的？
效果满意吗？"

→ 用提问引导客户意识到现状的问题
→ 不要反驳，用提问让他自己发现

跟进提问：
"这个环节一年花多少钱？"
"有没有出现过XX问题？"
"如果有一种方式能帮您省XX/提高XX，您有兴趣了解一下吗？"
```

## 异议4："已经有供应商了"

### 心理分析

有供应商不代表满意，只是**懒得换**（换供应商有风险和成本）。

### 处理方式

```
"那挺好的，说明您对这个确实有需求。
您跟现在的供应商合作多久了？
各方面还满意吗？有没有觉得可以更好的地方？"

→ 找到现有供应商的薄弱环节
→ 不要说竞品坏话，让客户自己说
→ "那我们有空可以聊聊，不一定要换，多一个选择也不错"

深入提问：
"服务响应速度快吗？"
"有没有遇到过交期延迟的问题？"
"价格方面有竞争力吗？"
"技术支持到位吗？"

→ 等客户说出不满意的地方，你就有了切入点
```

## 异议5："预算不够"

### 心理分析

两种可能：
- A：真没预算（预算花完了/公司控制严）
- B：有预算但优先级不够（觉得你不值这个钱）

### 处理方式A（真没预算）

```
"理解，那咱们换个思路。
先用基础版解决最核心的问题，XX元就能起步。
等见效了再升级，这样压力小很多"

或：
"那您下一个预算周期是什么时候？
我们现在先把方案做好，到时候直接执行"
→ 提前布局，锁定下个周期的需求
```

### 处理方式B（优先级不够）

```
"理解，预算确实要花在刀刃上。
不过您算一下，这个问题拖一年，
损失的成本是这个方案的X倍。
如果我能帮您3个月见效，值不值得优先安排？"

→ 强调不解决问题的成本 > 解决问题的成本
→ 帮客户重新排序预算优先级
```

## 异议6："我要跟领导/合伙人商量"

### 心理分析

两种可能：
- A：拖延借口（不想直接拒绝）
- B：真需要审批（没有决策权）

### 判断方法

```
问："那您个人觉得这个方案怎么样？"
→ 如果客户说"我觉得不错" → 真需要审批
→ 如果客户含糊其辞 → 可能是借口
```

### 处理方式

```
"没问题，那您看需要我准备什么材料，
帮您跟领导汇报更方便？
要不这样，我出一个简单的方案对比表，
您直接拿给领导看，一目了然"

→ 主动帮客户准备向上汇报的材料
→ 甚至可以提议一起跟领导开会：
"如果您觉得方便，我可以一起去跟您领导汇报，
现场答疑，这样效率更高"
```

## 异议7："别家更便宜"

### 心理分析

大部分情况是在**试探你的底线**，不一定真有更便宜的竞品。

### 处理方式

```
"王总，便宜的方案确实有，但您要看清楚3件事：
1. 功能一样吗？（很多低价是阉割版）
2. 服务一样吗？（出了问题有人管吗）
3. 能用多久？（便宜但用不了半年就要换）

我建议您不要只看价格，看整体性价比。
我们贵一点，是因为[差异化价值]。"

→ 不打价格战，打价值战
→ 引导客户关注总拥有成本（TCO），不只是初始价格
```

### 如果竞品真的更便宜也更好

```
诚实是最好的策略：
"王总，如果对方确实更便宜功能也一样，
那您选对方我没意见。
但我想提醒您注意[XX风险/XX隐性成本]，
如果有任何问题，随时找我"

→ 保持关系，等竞品出问题时你还有机会
→ 不要说竞品坏话（会显得你心虚）
```

## 异议8："我先试试免费的"

### 心理分析

对你还不够信任，想先验证效果。

### 处理方式

```
"可以的，我们正好有免费试用期。
不过我建议您试的时候重点关注这3个方面：___
这样您能更准确地判断适不适合。

试用期间有任何问题随时找我，
我帮您做配置和答疑，不额外收费"

→ 给试用期，但要引导测试重点
→ 试用期间保持高频接触（不是放任不管）
→ 设定试用期结束后的转化节点：
"试用期结束后，我们一起评估一下效果，
如果合适就继续，不合适也没关系"
```

## 异议处理万能公式

```
LAER模型：

L - Listen（倾听）：让客户把话说完
A - Acknowledge（认可）：共情，表示理解
E - Explore（探究）：找到真实原因
R - Respond（回应）：针对性解答

示例：
客户："太贵了"
L：（听完）
A："我理解您的感受"
E："您是觉得整体价格高，还是某个模块的性价比不够？"
R：针对具体问题回应
```

## 异议9："[竞品XX]是免费的，你们为什么收费？"

### 心理分析

客户拿免费竞品比，有3种情况：
- A：真的在用免费竞品，想确认付费值不值
- B：听说过免费竞品，拿来压价
- C：预算有限，免费是最安全的选择

### 判断方法

```
问："您现在在用XX（免费竞品）吗？用了多久？"
→ "在用，用了3个月" → A类（有真实体验，针对性突破）
→ "没用过，听人说有免费的" → B类（拿来说事，教育认知）
→ "预算不多，想找免费的先用着" → C类（真没钱）
```

### 处理方式

```
核心逻辑：免费的东西，成本最高。

"王总，免费的产品确实有，但您想想：
1. 免费的产品靠什么赚钱？→ 卖你的数据/加广告/功能阉割后收费
2. 免费的产品出了问题谁管？→ 没有客服/没有SLA/随时停服
3. 免费的产品能定制吗？→ 不能。你的业务是独特的，通用工具解决不了特定问题

您算一笔账：
→ 用免费工具，每个月花XX小时手动处理它搞不定的事
→ 你的时间成本是XX元/小时
→ 一个月浪费XX元的时间，一年浪费XX元
→ 我们的系统XX元/年，帮你省下这些时间

更重要的是：
→ 免费工具随时可能关停/改收费/限功能
→ 你积累的数据/配置全部白费
→ 换系统的迁移成本远高于直接用付费的

如果您确实预算有限，可以先从基础版开始，XX元/月起步。"

免费 vs 付费对比表（准备给客户看）：

| 维度 | 免费工具 | 我们的付费版 |
|------|---------|------------|
| 功能 | 基础功能，高级功能要付费 | 全功能 |
| 服务 | 无客服/社区论坛 | 1对1专属客服/SLA保障 |
| 定制 | 不能定制 | 支持定制开发 |
| 数据 | 可能卖你的数据 | 数据归你/保密协议 |
| 稳定性 | 随时可能关停 | 合同保障/99.9%可用性 |
| 迁移成本 | 换工具=从头再来 | 持续迭代/数据可导出 |
```

### 如果客户真的没钱

```
"理解，预算有限先用免费工具也没问题。
不过建议您：先把核心流程跑通，等业务起来了我再帮您升级。
我先把联系方式留着，您有任何问题随时找我。"

→ 不要硬推！留关系，等客户成长
→ 免费用户是你的未来客户，不要得罪
```

## 异议10："我要跟技术部门确认一下兼容性/对接"

### 心理分析

两种可能：
- A：真需要技术验证（B2B正常流程，特别是IT相关产品）
- B：技术是借口，真实原因是没被说服/不想推进

### 判断方法

```
问："您个人觉得这个方案怎么样？功能上能满足需求吗？"
→ "我觉得不错，就是要跟IT确认" → A类（真需要技术确认）
→ "嗯...还行吧" → B类（没被说服，技术是借口）

追问："技术部门主要会关注哪些方面？
是数据安全、API接口、还是系统集成？"
→ 能说出具体关注点 → A类
→ 说不出来/很笼统 → B类
```

### 处理方式A（真需要技术确认）

```
"太好了，技术部门的专业意见很重要。
为了让他们更高效地评估，我准备几样东西：

① 技术对接文档（API文档/数据流图/安全报告）
② 兼容性清单（支持哪些系统/浏览器/设备）
③ 部署方案（需要什么环境/多少时间/IT需要做什么）
④ 同行业技术对接案例（XX公司IT团队怎么评估的）

您看还有什么他们特别关心的？
我也可以直接跟你们的技术同事沟通，效率更高——
很多技术问题，技术人员对技术人员聊，10分钟就清楚了。"

⚠️ 关键动作：
├─ 主动提供技术材料（不要让IT来追你要）
├─ 争取直接跟IT对话（越过中间人传话的损耗）
├─ 提前了解客户的IT环境（用什么系统/什么架构）
├─ 找到你方的技术对接人（让技术对技术）
└─ 给IT一个简单的评估checklist（降低他们的工作量）
```

### 处理方式B（技术是借口）

```
客户其实没被说服，但不好意思直说。

不要揭穿！换一个角度：
"理解，技术确认确实很重要。
不过在等技术反馈之前，我想确认一下：
从业务角度，您觉得这个方案能帮到你们吗？
如果效果方面有什么顾虑，我们可以先聊聊。"

→ 把技术话题拉回业务价值
→ 如果客户开始谈业务顾虑→找到了真实异议
→ 如果客户还是说"先让技术看看"→可能真的只是没兴趣
→ 给一个时间节点："技术大概需要多久评估？
我X天后跟您确认进度？"
```

### 预防技术异议（在需求挖掘阶段就处理）

```
在Phase 4需求挖掘时，主动问：
"你们现在用的什么系统？"
"IT部门对新系统接入有什么要求/标准？"
"之前有没有上过类似的系统？体验怎么样？"

→ 提前了解IT环境
→ 提前准备技术方案
→ 甚至提前跟IT建立联系
→ 不要等到报价后才发现技术卡点
```

## 常见异议速查表

| 客户说的 | 真实原因 | 核心策略 |
|---------|---------|---------|
| "太贵了" | 觉得不值 | 价值塑造+拆解+对比 |
| "考虑一下" | 有顾虑 | 变模糊为具体 |
| "不需要" | 没看到痛点 | 用提问引导发现问题 |
| "有供应商了" | 懒得换 | 找现有供应商薄弱点 |
| "预算不够" | 优先级不够或真没钱 | 基础版/算拖延成本 |
| "跟领导商量" | 无决策权/拖延 | 帮准备汇报材料 |
| "别家更便宜" | 试探底线 | 打价值战 |
| "先试免费" | 不信任 | 给试用+重点引导 |
| "竞品免费" | 压价或真没钱 | 算时间成本+免费隐藏成本 |
| "跟技术确认" | 真验证或没被说服 | 给技术材料+直接对话IT |
| "以后再说" | 没紧迫感 | 制造紧迫感/锁定时间 |
| "你们公司没听过" | 不信任 | 案例背书+免费试用 |
| "效果能保证吗" | 怕风险 | 风险逆转+合同保障 |
| "功能不够全" | 需求没满足 | 定制方案/功能路线图 |
