# 用户标签设计｜郭亿易

把业务目标、用户行为和现有字段转换为标签树、定义、取值规则和更新频率。

## 工作流程

1. 识别客户阶段：围绕“只保留能触发动作或支持分析的标签”处理，不扩大到无关任务。
2. 核对事实与权限：以用户提供的业务目标、用户行为和现有字段为事实边界。
3. 生成可发送回应：形成标签树、定义、取值规则和更新频率中的对应部分。
4. 记录标签与后续动作：使用“禁止用主观贬义词给用户贴标签”作为最终门槛。

## 输入最低要求

- 接收：业务目标、用户行为和现有字段。
- 明确目标平台、时间范围、数量或格式；缺失时列出假设，不静默补造事实。
- 对个人信息、订单信息、商业数据和未公开资料执行最小披露。

## 输出合同

- 首段先给可执行结论，再给标签树、定义、取值规则和更新频率。
- 每个判断附输入证据、来源位置或“待确认”标记。
- 同时列出阻断项、风险项和下一步负责人；不把建议伪装成已完成动作。

## 质量门槛

- 只保留能触发动作或支持分析的标签。
- 禁止用主观贬义词给用户贴标签。
- 不复制第三方 Skill 的文字、代码或品牌；只解决本 Skill 声明的中文垂直任务。
