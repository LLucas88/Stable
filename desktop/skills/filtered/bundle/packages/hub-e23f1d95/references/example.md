# 用户标签设计示例

## 示例任务

请根据我提供的业务目标、用户行为和现有字段，完成用户标签设计，输出标签树、定义、取值规则和更新频率；同时标注缺失信息和发布前必须人工确认的风险。

## 调用前

只有原始业务目标、用户行为和现有字段，信息分散、判断口径不统一，CRM与私域运营无法直接进入下一步执行。

## 调用后

得到结构化的标签树、定义、取值规则和更新频率，关键结论附依据，缺口和风险单独列出，可直接分配负责人并验收。

## 对比

| 维度 | 调用前 | 调用后 |
|---|---|---|
| 信息结构 | 原始资料混杂 | 按任务目标分层 |
| 决策依据 | 依赖个人经验 | 结论绑定输入证据 |
| 执行状态 | 不清楚下一步 | 负责人、动作和门槛明确 |
| 风险控制 | 容易遗漏 | 缺失、合规和人工确认项显式标记 |

## 验收项

- 只保留能触发动作或支持分析的标签。
- 禁止用主观贬义词给用户贴标签。
- 输出未虚构资料中不存在的事实、数据或用户反馈。
