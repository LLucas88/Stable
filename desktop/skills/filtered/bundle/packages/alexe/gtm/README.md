# 🚀 Go-to-Market (GTM)

[← Back to all domains](../README.md)

Skills for planning launches, developing positioning and messaging, designing packaging, and enabling sales and customer success teams.

A great product with a bad launch is an invisible product. GTM is where product value gets translated into market action — messaging that resonates, pricing that converts, sales teams that can explain the "why," and launches that don't fall apart because CS wasn't briefed. This domain gives your agent the structure to get all of that right.

---

## 📋 What's inside

This domain covers the full GTM arc:

```text
target segment + product value
    ↓
value proposition
    ↓
positioning & messaging
    ↓
packaging & pricing
    ↓
sales battlecards    sales & CS enablement
    ↓                       ↓
        launch plan
            ↓
    launch readiness checklist
```

The flow moves from defining the message to building the materials to coordinating the launch. Skills work independently too — you can update a battlecard without touching pricing.

## 🔗 How the skills connect

**The messaging pipeline:**
- `craft-value-proposition` defines the core benefit → feeds `develop-positioning-messaging`
- `develop-positioning-messaging` builds the full messaging framework → feeds `plan-product-launch` and `enable-sales-cs`

**The commercial pipeline:**
- `support-pricing-packaging` analyzes pricing structures → feeds `design-packaging-tiers`
- `design-packaging-tiers` creates tier structure with upgrade paths → feeds `enable-sales-cs`

**The enablement & launch pipeline:**
- `create-sales-battlecard` builds competitive response materials → feeds `enable-sales-cs`
- `enable-sales-cs` prepares sales and CS with materials and workflows → feeds `plan-product-launch`
- `plan-product-launch` structures the launch coordination → feeds `build-launch-readiness-checklist`
- `build-launch-readiness-checklist` ensures cross-functional readiness before go-live

**Cross-domain connections:**
- Value proposition draws from `apply-jtbd-framework` (product-discovery) and `define-strategic-positioning` (product-strategy)
- Pricing feeds `build-business-case` (business-commercial)
- Launch connects to `plan-delivery-collaboration` (product-planning) and `analyze-experiment-results` (experimentation)

## 🛠️ Skills in this domain

### 1. `craft-value-proposition`

Use this when a product or feature lacks a clear value proposition, or messaging describes features instead of user outcomes.

What it does:
- Identifies the target user and their primary job or problem
- Articulates the outcome the product delivers (not features — outcomes)
- Identifies why this product delivers the outcome better than alternatives
- Tests the proposition for specificity ("saves time" is not specific enough)

---

### 2. `develop-positioning-messaging`

Use this when different teams are saying different things about the product, or messaging is too feature-centric.

What it does:
- Defines the target audience for this messaging
- Writes a positioning statement (for-who-who-unlike-our product-because)
- Creates 3 key messages with supporting proof points
- Ensures messaging is outcome-centric, not feature-centric

---

### 3. `support-pricing-packaging`

Use this when a new product needs a pricing decision, or current pricing is creating customer friction or revenue leakage.

What it does:
- Identifies the value metric (what customers get more of as they pay more)
- Reviews current pricing and identifies friction points
- Maps pricing options to customer segments
- Evaluates 2–3 structures with trade-offs

---

### 4. `design-packaging-tiers`

Use this when adding tier structure for the first time, or existing tiers don't create a clear upgrade path.

What it does:
- Defines the value metric driving tier differentiation
- Maps segments to willingness to pay and primary value drivers
- Designs 3–4 tiers with clear "who it's for" and upgrade triggers
- Ensures free tiers balance adoption and conversion

---

### 5. `create-sales-battlecard`

Use this when sales is losing deals to a specific competitor, or competitive messaging is inconsistent across the team.

What it does:
- Identifies the competitor's primary value proposition
- Lists 3–5 most common objections and writes factual, confident responses
- Identifies your strongest win reasons and honest areas where competitor is stronger
- Keeps it objective — no disparagement

---

### 6. `enable-sales-cs`

Use this when a launch requires sales and CS preparation, or sales is pitching with outdated messaging.

What it does:
- Defines what sales and CS need to know: positioning, value prop, use cases, objections
- Writes a product overview brief (1-pager) and objection handling guide
- Defines what to demo and how
- Identifies escalation paths for complex questions

---

### 7. `plan-product-launch`

Use this when a product or feature is approaching launch and needs coordinated readiness, channels, and success criteria.

What it does:
- Defines launch readiness criteria across all functions
- Identifies launch audience and phasing (internal → beta → soft → full)
- Defines channels and messaging per audience
- Builds pre-launch, launch day, and post-launch checklists with rollback criteria

---

### 8. `build-launch-readiness-checklist`

Use this when past launches had post-launch surprises, or a multi-team launch requires cross-functional coordination.

What it does:
- Maps launch-critical tasks by function (product, engineering, CS, sales, marketing, legal, data)
- Defines owner, definition of done, and deadline for each task
- Identifies go/no-go criteria (binary, pre-agreed)
- Defines rollback or mitigation plan

## 🧭 How to use this domain

### Option 1: Full GTM build

Use this when preparing a new product or major feature for market.

Typical path:
1. `craft-value-proposition`
2. `develop-positioning-messaging`
3. `support-pricing-packaging` → `design-packaging-tiers`
4. `create-sales-battlecard` + `enable-sales-cs`
5. `plan-product-launch` → `build-launch-readiness-checklist`

### Option 2: Enter in the middle

- Product exists but messaging is weak → start with `craft-value-proposition`
- Launch is next week → start with `plan-product-launch` or `build-launch-readiness-checklist`
- Losing deals to a competitor → start with `create-sales-battlecard`
- Sales is pitching wrong → start with `enable-sales-cs`
- Pricing feels off → start with `support-pricing-packaging`

## ⚠️ What this domain protects against

Common GTM failure modes:

- **Feature-speak instead of value.** "We added real-time sync" means nothing to a buyer. `craft-value-proposition` forces outcome language.
- **Positioning for everyone.** Which means positioning for no one. `develop-positioning-messaging` requires a specific target audience.
- **Launches without rollback.** No rollback criteria = gambling. `plan-product-launch` requires them.
- **CS learns about the launch from customers.** `build-launch-readiness-checklist` gates launch on cross-functional readiness.
- **Battlecards that disparage competitors.** Red flag for buyers. `create-sales-battlecard` keeps responses factual and confident.
