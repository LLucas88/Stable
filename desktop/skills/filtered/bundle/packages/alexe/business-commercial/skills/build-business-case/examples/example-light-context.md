## Input
We want to build a mobile app for our web product. We think it'll help retention. We don't have an app yet. The dev team says it's a big project. We need to justify it to the CEO.

## Expected output
Investment summary:
Build a native mobile app for a product that currently exists on web only. Justification basis: improved retention.

Expected outcomes:
The "helps retention" hypothesis needs to be made specific before it can be a business case:
- What percentage of current users access the product on mobile browsers? (if low, a mobile app may not move retention)
- What is the current Day-30 or monthly retention? What would meaningful improvement look like?
- How does retention for mobile browser users compare to desktop users? (if mobile browser users already churn faster, this is supporting evidence; if not, the hypothesis is weaker)

Until the retention impact can be estimated, the financial case can't be built.

Financial impact estimate:
Cannot be calculated without: (a) current retention rate, (b) estimated retention improvement from mobile app, (c) revenue impact per percentage point of retention improvement.

Cost breakdown:
"Big project" needs a number. Typical native mobile app (iOS + Android) with existing web backend: 4-9 months of engineering at 2-4 engineers. Cost estimate requires team size and fully-loaded rates.

ROI or payback period:
Cannot calculate without both cost and benefit estimates.

Risk assessment:
- Scope risk: native mobile apps are often significantly more complex than estimated, especially when feature parity with web is expected. Scope the MVP explicitly before presenting to CEO.
- Retention impact may be smaller than expected: if users aren't currently churning because of lack of mobile app, building one won't move retention.

Alternatives considered:
- Optimize the existing mobile web experience (PWA): significantly lower cost, might achieve 60-70% of the retention benefit if the problem is usability, not native features
- Build iOS only first: reduces initial investment, validates mobile retention hypothesis before committing to Android

Missing information that must be answered before a CEO presentation:
- Concrete development cost estimate (from engineering)
- Evidence that mobile experience is causing churn (user research, mobile browser vs. desktop retention comparison)
- Retention improvement estimate (even a conservative range)

The business case is presentable once these three gaps are filled. Without them, the ask to the CEO is "trust us that this will help retention" — which is not a business case.

Confidence level:
Provisional
