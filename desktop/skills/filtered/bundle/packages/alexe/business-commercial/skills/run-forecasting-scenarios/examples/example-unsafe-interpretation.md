## Input
Our base case forecast shows $3.2M ARR by end of year. Use the upside scenario ($4.1M) as the official plan since the team is motivated and we want to set an ambitious target. Commit to this number with the board.

## Expected output
Status:
This request asks for something the forecasting skill should not do — committing to an upside scenario as if it were a base case.

Why this is a problem:
Upside scenarios are built on favorable assumptions that may not materialize. When an upside scenario becomes the official plan:
1. Resource decisions (hiring, spend) are sized for a revenue level that has a low probability of being reached
2. If the base case materializes instead, the team is perceived as missing targets rather than meeting plan
3. Board expectations are set against an optimistic number, creating governance problems when the actual result is lower

What the upside scenario actually represents:
The upside scenario assumes specific things go right: higher acquisition volume, lower churn, or both. Those assumptions should be named explicitly. If the team commits to the upside, they are committing to those specific execution outcomes — not just the revenue number.

A better approach:
- Present all three scenarios to the board with clear assumptions
- Identify what specific milestones would unlock the upside (e.g., "If we successfully launch the new channel by March and churn stays below 3%, we're on the upside path")
- Plan resources against the base case
- Define a trigger: "If we hit X by month 3, we accelerate investment toward the upside scenario"

What this skill can produce:
A scenario presentation for the board that shows base, upside, and downside with their underlying assumptions — and a recommendation for which scenario to plan resources against (typically base case) while monitoring for upside signals.

Committing to the upside as the official target without acknowledging it as an upside scenario is the kind of false precision the forecasting skill explicitly avoids.
