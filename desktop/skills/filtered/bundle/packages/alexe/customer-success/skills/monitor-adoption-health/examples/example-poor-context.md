## Input
How do I know if my customers are healthy?

## Expected output
To define adoption health monitoring, two inputs are needed: what your product does (so we can define what healthy usage looks like), and what data you currently have available.

What is needed:
- Product type: what does your product do? What is the core value action?
- Available data: what usage signals do you collect? (Logins, feature events, billing, support)

Without knowing the product, "healthy" cannot be defined — healthy usage for a daily productivity app looks completely different from healthy usage for a quarterly compliance tool.

Suggested next inputs:
- "Our product is [description]. The main thing a successful user does is [action]."
- "We currently track [login data / feature events / NPS / other]"
- "Our customers are [segment] and they typically [usage pattern]"
