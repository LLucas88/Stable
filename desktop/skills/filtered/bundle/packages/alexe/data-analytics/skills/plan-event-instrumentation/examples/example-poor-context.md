## Input
We need analytics for our new feature. What events should we track?

## Expected output
Event tracking can't be planned without knowing what the feature does.

What is known:
- There is a feature that needs analytics

What must be confirmed before starting:
- What does the feature do? (user flow, key actions)
- What decisions should the tracking data support? (conversion, engagement, adoption, retention)
- What metrics does the team care about for this feature?
- What analytics tooling is in use?
- Is there an existing event naming convention?

Suggested next inputs:
- Feature description and user flow
- Key metrics or decisions this instrumentation should support
- Analytics tool (Amplitude, Mixpanel, Segment, custom, etc.)
- Existing event naming convention if one exists

Without a feature description and metric goals, any event list produced would be generic and likely to miss the data that actually matters.

Confidence level:
Provisional
