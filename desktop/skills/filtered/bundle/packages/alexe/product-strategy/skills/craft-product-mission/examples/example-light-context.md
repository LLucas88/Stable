# Example: Light Context

## Input

**Product:** Productivity app for freelancers
**Target segment:** Freelancers who want to manage their work better
**Core value:** Help them stay organized

## Output

### Mission statement (provisional)
We help freelancers manage their work and client relationships in one place, so they spend less time on admin and more time doing the work they're paid for.

### Who it serves
Freelancers — but the segment is too broad. The mission above is provisional and should be narrowed by:
- Type of freelancer (creative, technical, consulting?)
- Primary pain (client communication, invoicing, task tracking, time management?)
- Stage (new freelancers building habits vs. experienced freelancers scaling?)

### Core job or problem addressed (assumed)
Freelancers juggle clients, tasks, and admin across too many tools, leading to dropped balls and wasted time. This is an assumption — needs validation.

### Value delivered
Reduced admin overhead; more time for billable work. Assumed based on typical freelancer pain; not confirmed by research.

### Specificity test: what would this mission say no to?
In its current form — very little. The mission as written could describe Notion, Trello, FreshBooks, or a CRM. It needs to answer: which part of freelance work is the focus, and what makes this product the right tool for that specific job?

### Confidence level
Provisional

### Open questions
1. What is the primary user problem — task management, client communication, invoicing, or all three?
2. What does "organized" look like for this user — fewer missed deadlines, faster invoicing, clearer pipeline?
3. Is the product already live? If so, what do retained users say it does for them?
4. Who are the main competitors and how do users compare us to them?
