# Example: Light Context

## Input

**Product:** Project management tool for creative agencies
**Product capabilities:** Task boards, timeline view, client portal, file sharing
**Business goal:** Grow MRR by 3x in 18 months

## Output

### Positioning hypothesis (provisional)
Based on limited context, a provisional positioning hypothesis:

For creative agencies managing client projects, [Product] is the project management tool built for client-facing work — combining internal task management with a client portal so agencies stop switching between project tools and client communication platforms.

This is a hypothesis, not a validated position. It requires stress-testing with customer data.

### Target segment (provisional)
Creative agencies (design, marketing, video) running multiple concurrent client projects. Team size: likely 5–50 people. Needs validation — are the retained customers agencies, or is it broader?

### What is still unknown
1. **Who is actually retained?** Without retention data or ICP analysis, the segment is guessed. Pull the top 20 retained customers and identify what they have in common.
2. **Why do customers choose this over Asana/Monday/Teamwork?** Win reasons define the differentiation — without them, the point of differentiation is assumed.
3. **What does the client portal do that competitors don't?** If it's table stakes, it's not a differentiator.

### What would strengthen this positioning
- 5–10 customer interviews asking: "Why did you choose us over alternatives?"
- Churn analysis: who leaves and why?
- Competitive win/loss review for last 20 deals

### Confidence level
Provisional — positioning hypothesis is directionally reasonable but not validated. Do not anchor GTM or roadmap decisions on this without further research.
