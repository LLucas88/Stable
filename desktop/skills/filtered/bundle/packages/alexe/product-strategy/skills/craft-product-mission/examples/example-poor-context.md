# Example: Poor Context

## Input

"Write a mission statement for our product."

## Output

### Status
Insufficient context to write a meaningful mission statement.

### What is missing

A mission statement requires:
1. **Who the product serves** — a specific user or customer segment, not "everyone"
2. **What the product does** — the core job or problem it addresses
3. **What value it delivers** — the outcome for the user, not the feature list

Without these, any mission produced would be generic and unusable for making product decisions.

### Discovery questions

Before writing a mission, answer:

1. What is the product? What does it do?
2. Who is the primary user — be as specific as possible (role, company type, context)?
3. What is the main problem the product solves for them?
4. What does the user get from the product that they couldn't easily get elsewhere?
5. Is there an existing mission or vision to refine, or is this being written from scratch?

### What happens next

Once segment, core job, and value are known, this skill can produce:
- A mission statement
- A specificity test (what this mission would say no to)
- A confidence assessment

If the product is not yet defined enough to answer these questions, consider using `identify-problem-opportunity` or `develop-persona-segment` first.
