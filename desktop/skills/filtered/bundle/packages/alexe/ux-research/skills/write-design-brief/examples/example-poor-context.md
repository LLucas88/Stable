## Input
Write a design brief for a new feature.

## Expected output
A design brief gives designers the problem context they need to start work. To write one, I need to understand the problem.

What is known:
- A new feature is being planned and needs a design brief

What must be confirmed:
- What problem does this feature solve? (from the user's perspective, not the business's)
- Who is the target user?
- What outcome should the feature achieve?
- What constraints exist? (technical, business, time, brand)
- What should this design effort not address? (non-goals)
- How will the team know the design is successful? (success criteria)

A brief that specifies the solution is a spec, not a brief. The purpose of a design brief is to frame the problem clearly so designers can explore solutions.

Suggested next inputs:
- The problem to solve (stated from the user's perspective)
- The target user or segment
- The desired outcome
- Known constraints
- Any research, data, or prior design work that's relevant

Without a problem statement and target user, the brief would be too generic to guide design work.

Confidence level:
Cannot write — no problem, user, or context provided
