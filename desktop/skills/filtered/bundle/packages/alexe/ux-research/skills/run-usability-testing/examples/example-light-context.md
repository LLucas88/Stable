## Input
We have a telehealth app and want to test our new booking flow. We have a prototype ready. Can you help us set up usability testing?

## Expected output
Test tasks (draft — based on a typical telehealth booking flow):

Task 1: Book an appointment
- Scenario: "You want to see a doctor online. Find a doctor and book a time."
- Success criteria: Completes booking without assistance

Task 2: Complete any pre-visit steps
- Scenario: "Prepare for your appointment by completing whatever the app asks you to do."
- Success criteria: Completes all required steps. Note where participants hesitate or get confused.

Task 3: Find your appointment details
- Scenario: "You've booked. Find out when your appointment is and how to join."
- Success criteria: Locates confirmation details

Testing method:
- Moderated, remote sessions recommended (allows follow-up questions)
- 5–6 participants
- 30–45 minutes per session

Participant criteria (draft):
- People who have booked a medical appointment online before
- Age range: to be defined based on your user base
- Exclude internal team members

Test script outline:
1. Introduction and think-aloud instructions
2. Tasks (in order above)
3. Debrief: what worked, what was confusing, overall impression

Missing information:
- What the booking flow includes (how many steps? intake form? insurance?)
- What specific concerns or hypotheses the team has about the flow
- Target user profile (age range, tech comfort level, telehealth experience)
- Whether this is moderated or unmoderated, remote or in-person
- Who will moderate the sessions
- How participants will be recruited
- Timeline

Suggested next steps:
1. List the specific steps in the booking flow
2. Identify which steps you think might cause problems (these become focus areas)
3. Define participant criteria based on your actual user base
4. Then finalize tasks and test script

Confidence level:
Provisional — tasks are reasonable for a telehealth booking test but should be customized to the actual flow.
