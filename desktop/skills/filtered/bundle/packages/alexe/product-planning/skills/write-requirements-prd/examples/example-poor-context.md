## Input
Write requirements for a notifications feature.

## Expected output
Requirements cannot be written without knowing the user and the problem.

"Notifications feature" could mean:
- Push notifications for a mobile app
- In-app notification center
- Email digest
- Real-time alerts for specific events
- All of the above

These have completely different requirements.

What is needed before writing:
- What type of notifications? (push, in-app, email, SMS)
- What events trigger a notification? (user actions, system events, scheduled reminders)
- Who receives notifications? (all users, specific segments, specific roles)
- What problem is this solving? (re-engagement, real-time updates, alerts)
- What does success look like? (notification open rate, downstream action, churn reduction)

Without these inputs, any requirements produced would be fictional specifications for an imaginary feature that may not match what needs to be built.

Suggested next inputs:
- The specific trigger events for notifications
- The user type receiving them
- The desired outcome (what should change after this ships?)
- Any constraints (platform, opt-in requirements, regulatory)
