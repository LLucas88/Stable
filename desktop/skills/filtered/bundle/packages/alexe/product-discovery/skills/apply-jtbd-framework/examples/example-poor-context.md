## Input

"Apply JTBD to our app."

## Expected output

Cannot apply the JTBD framework without knowing what product or user context to apply it to, and without research data to ground the job statements.

A job statement produced without data is not a finding — it is a guess that carries the appearance of structure. Acting on it risks building for an imagined user motivation rather than a real one.

To apply JTBD meaningfully, provide:
1. What product or feature area are we applying this to?
2. What user interviews or research data are available?
3. What is the known or suspected user problem or motivation?
4. Who is the target user segment?

JTBD hypothesis template (for use once context is available):

Job statement format: "When [situation or trigger], I want to [functional motivation], so I can [expected outcome]."

Dimensions to map:
- Functional job: What task is the user trying to accomplish?
- Emotional job: How do they want to feel (or avoid feeling) while doing it?
- Social job: How do they want to be perceived by others?
- Struggling moment: What triggered the search for a solution?
- Competing solutions: What else is being used or considered for the same job?

Recommended next step: If no research data exists, run user interviews first using run-user-interviews, then return to this skill with interview notes to map the job.
