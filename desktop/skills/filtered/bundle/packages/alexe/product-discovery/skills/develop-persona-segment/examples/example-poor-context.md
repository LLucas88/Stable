## Input

"We need user personas for our app."

## Expected output

Cannot build research-grounded personas without user data.

Producing personas from assumptions alone risks designing for an imagined user — a frequent and costly mistake. Assumption-based personas look useful but embed unverified beliefs into product decisions that are then difficult to reverse.

To produce personas that are useful for product, design, and messaging decisions, provide at least one of:
- Interview notes or synthesis from user research
- Behavioural usage patterns (session frequency, feature engagement, retention cohorts)
- Support ticket themes or NPS comment analysis
- Survey data with open-ended responses

Without this, the only honest output is a blank persona template:

Persona name: [to be defined from research]
Primary goals: [research needed]
JTBD: [research needed]
Key pain points: [research needed]
Context of use: [research needed]
Behavioural patterns: [research needed]
Evidence quality: Assumed

Recommended next step: Run 5–8 user interviews using run-user-interviews before attempting persona development. If some data already exists (support tickets, NPS comments), synthesise it first using synthesize-qualitative-research, then return to this skill.
