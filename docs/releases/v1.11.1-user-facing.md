# Stable v1.11.1｜把想法做成作品，把成果改到满意

**从一张图片、一份报告，到一段值得继续的对话，这次更新让创作、修改和整理更连贯。**

你可能遇到过这样的时刻：报告已经生成，只想改一个标题，却又要描述半天；对话里有个很好的方案，过几天却翻不到；想给活动做张图，还得另开工具；换了 AI 应用，之前积累的讨论也很难接着用。

从 **1.0.03 到 v1.11.1**，Stable 围绕这些具体问题，补齐了一批日常工作里真正用得上的能力：独立的 Design 图像创作入口、可以直接动手修改的 HTML 报告、对话分支与章节、WorkBuddy / Codex 数据导入，以及更完整的联网搜索、网页正文读取和生图链路。

这是一份跨版本累计更新说明。已经在 1.0.03 中提供的文件粘贴、文件定位、技能市场、知识库等能力继续保留；下面重点介绍这次发生的变化。

## 先看这次最值得体验的变化

| 你想做的事 | v1.11.1 带来的变化 |
| --- | --- |
| 给活动、报告或品牌做一张配图 | 打开 Design，选择比例、尺寸和张数，在同一对话里讨论并生成图片 |
| 把 AI 生成的 HTML 报告改到满意 | 直接改文字、调样式、换图片；选中元素或框出区域，让 AI 接着修改 |
| 在一个好方案上试另一条路 | 从指定回答创建对话分支，保留原来的讨论 |
| 快速找回长对话里的关键结论 | 把回答固定为章节，通过目录跳转 |
| 把已有 AI 工作积累带过来 | 选择导入 WorkBuddy / Codex 的聊天、项目、技能、记忆和可识别连接器配置 |
| 查资料并核对来源 | 搜索公开网页、读取正文，再结合实际来源生成回答 |
| 同时跟进多个任务 | 在活动列表里查看运行、待审批、待回答和未读任务 |

## 01 · Design：从一句想法，开始一张图

活动海报、文章封面、报告插图、社交媒体配图……现在可以从侧栏的 **Design · 图像创作** 入口开始。

你可以先说明用途和风格，添加参考图片，再设置成品规格。生成后继续在同一个对话里讨论下一版，创作过程与交付文件留在一起。

**这次新增了什么？**

- **独立的创作入口。** Design 与普通聊天分开进入，可以回到已有设计会话继续工作。
- **“图片生成”和“对话”两种输入模式。** 新建 Design 默认进入图片生成；提交生图请求后切回对话，方便查看、讨论和补充要求。需要再次生成时，主动切回图片生成即可。
- **参考图与编号引用。** 支持上传、拖入和粘贴图片，在输入框使用 `@` 选择“图1”“图2”等参考对象。
- **常用画面比例。** 支持 1:1、4:3、3:4、16:9、9:16，覆盖方形、横版和竖版需求。
- **标准与 2K 档位、自定义像素尺寸。** 可以直接填写宽高，并锁定比例联动调整。宽高范围为 512–2048 px，自动对齐到 32 的倍数，界面显示最终实际尺寸。
- **一次设置 1–4 张。** 图片逐张生成；生成失败时不会自动补发新的付费生成请求。
- **单独填写图中文字。** 将需要出现的标题、标语等文案与画面描述分开设置，便于模型核对。
- **每条生图消息保存自己的参数。** 历史消息和排队消息显示当次尺寸、档位和张数；修改下一条的设置，不会改变上一条记录。

**可以这样开始：**

> 为周末咖啡活动设计一张 3:4 竖版海报，参考图1的配色，整体轻松明亮。主标题写“周末，慢一点”。先生成 1 张。

**使用说明：** 当前 Design 由 GLM-5.3-FlashX 负责对话与任务组织，GLM-image 负责生成新图片，需要对应服务可用。参考图供任务模型理解风格和构图，GLM-image 接口本身接收文字；这不等同于原生参考图重绘、遮罩编辑或主体保真保证。多张生成的参数和队列已具备支持，具体成品仍需逐张检查。

## 02 · HTML 报告：看到哪里，改到哪里

一份报告生成后，往往还需要调整标题、突出重点、替换配图或补充说明。现在，这些修改可以直接在 Stable 的内置浏览器里进行。

打开本地 HTML / HTM 文件，点击地址栏旁的铅笔图标，即可进入可视化编辑。刚上传、还没有发送的 HTML 附件，也可以先打开查看和编辑。

### 小修改，直接动手完成

- **双击编辑文字。** 支持普通段落、带链接或加粗的富文本，以及受支持的脚本生成文字。
- **调整文字和区块样式。** 包括字体、字号、颜色、粗体、斜体、下划线、删除线、对齐、行高、透明度、背景、边框和链接。
- **选择更灵活。** 支持单选、Shift 多选、拖动框选，以及用方向键切换父级、子级和相邻元素。
- **图片直接处理。** 支持替换、裁剪和等比例缩放；编辑器保留原图索引，之后可以重新裁剪。
- **撤销和重做。** 支持 Ctrl+Z、Ctrl+Shift+Z / Ctrl+Y；Ctrl+S 可以手动保存。

### 大修改，把位置和要求一起交给 AI

**选中元素后点击“AI 编辑”**，例如：

> 把这张指标卡改成更醒目的样式，保留数字，补上一句通俗解释。

也可以开启 **“区域 AI 编辑”**，框出页面上的一块区域，包括空白位置：

> 在这里补充一段本月的重点结论，排成三张横向卡片。

Stable 会把原 HTML、选区可见区域的截图和修改要求加入聊天草稿。你可以继续补充、检查，再发送执行；加入草稿本身不会直接发出任务，也会保留原来已经写好的文字和附件。

### 修改过程也更容易保留

- 停止修改约半秒后自动保存，并显示保存结果。
- 保存失败时保留编辑内容和恢复草稿，可重试或另存副本。
- 检测到 AI 或其他程序修改同一文件时，检查版本冲突，避免直接覆盖不同版本。
- 替换和裁剪后的图片保存到报告自己的资源目录；另存副本时同步复制编辑器管理的图片资源。
- 对脚本生成的受支持元素保存修改记录，减少刷新后文字或样式被脚本重绘覆盖的问题。

**适用范围：** 当前支持获准写入的本地 UTF-8 HTML / HTM，单文件最大 20 MB。Canvas 图表的数据修改、响应式 `picture` 图片等仍需交给 AI 处理；远程图片需先替换为本地图片才能裁剪。另存副本会携带编辑器管理的图片，不会自动打包网站的全部外部脚本和样式。

## 03 · 好的对话，值得分支，也值得收藏

### 从这里，试试另一个方案

回答下方新增 **“从此处分支”**。它会把截至该条回答的历史复制到一个新对话，原对话继续保留。

例如，已经讨论出一版活动方案，你可以保留原方案，再从那条回答分出新对话，尝试“预算减半”或“改为线上活动”的版本，不必从头解释背景。

分支会建立新的运行会话；此前已经放行的具体操作不会直接作为新对话的授权。分支中的附件和项目路径仍可能指向原文件，因此它是讨论分支，并不是工作文件的独立备份。

### 把关键回答固定为章节

将方案定稿、分析结论、操作步骤等回答 **固定为章节**，就能从章节目录快速跳转。章节支持重命名和取消固定，重新打开对话后仍然保留。

回答操作区还提供复制、生成时间和 Trace 入口。查看过程、复用结论、回到关键节点，都更集中。

### 文件交付更清爽

生成文件改用 **类型图标 + 简短文件名** 的链接展示，完整路径可通过悬停查看，减少长路径和重复产物卡片占据对话空间。用户自己上传的附件仍保留卡片与原有操作。

## 04 · 长任务和多任务：更容易接着做

### 活动列表，集中查看需要你关注的事

侧栏增加活动入口，可以在项目列表与活动列表之间切换。

- 优先展示运行中、等待审批和等待回答的任务。
- 按本地日期整理，并显示项目、最近消息摘要和未读状态。
- 支持只看未读、全部已读，点击即可回到原对话。
- 活动摘要直接使用本地消息，不为列表摘要额外调用模型。

### 草稿和排队消息可以恢复

输入中的文字、附件、引用与排队消息按当前应用数据环境保存，界面重新加载后可以恢复。

恢复出来的队列默认暂停，先由你确认再继续。发送结果不确定的消息不会自动重发，需要核对后编辑或删除，减少重复执行和重复计费的风险。附件恢复依赖原文件仍然存在；如果保存失败，界面会明确提示。

连续上传附件也得到修复：多次上传完成时会合并最新附件状态，避免后完成的一次覆盖前一次；上传尚未完成时阻止发送。

### 对话标题更像任务名称

自动命名会优先提取“做什么、处理什么”，减少直接截取客套话或截断任务目标的情况。

短问题先用本地规则命名；符合条件的复杂任务在首次成功完成后，最多再进行一次有上限的模型命名。手动修改的标题受到保护，命名失败保留原标题，已有历史不会被批量重命名。

### 下一句话，可以先给你一个建议

符合条件的回答结束后，输入框可以显示下一步消息建议。按 Tab、右方向键或回车采纳到草稿，再次发送才会执行；Esc 可以关闭当前建议。

该功能可在设置中关闭。建议生成会使用当前模型额度；简单知识问答等场景会跳过额外的预测调用。

## 05 · 把 WorkBuddy / Codex 的积累带进来

过去的聊天、项目背景和工作偏好，不必只能留在原来的应用里。

在 **设置 → 数据导入** 中，选择 WorkBuddy 或 Codex，先扫描、预览，再选择需要导入的条目。

| 内容 | 导入后的使用方式 |
| --- | --- |
| 聊天会话 | 转为 Stable 本地对话，通过正常输入框继续讨论；主要保留用户问题和最终回答 |
| 项目 | 独立选择导入项目关联，不递归复制整个原项目目录 |
| 附件与产物 | 对来源中可识别且本地可读的文件建立副本；可以取消单个关联文件 |
| 技能 | 导入后按需手动调用 |
| 记忆与偏好 | 导入知识库，初始不启用，由你决定何时使用 |
| 连接器 | 将可识别的 HTTP/SSE 声明保存为未启用模板，补充凭据与允许工具后再启用 |

**导入由你选择。** 默认不勾选内容；相同来源、相同内容重复导入会跳过，来源内容改变后可以建立新副本。长历史会保留可检索的问答文件，续聊时按需读取。

**需要了解：** 这是手动导入，不是持续同步。源应用的登录凭据、思考日志、运行中的工具调用和原工具授权不会一起迁移；云端链接或导出材料里缺失的文件不会自动下载。当前新导入入口为 WorkBuddy 和 Codex，ChatGPT 仅保留已有导入历史的展示。

## 06 · 搜索、读网页、生成配图，可以在同一项任务里完成

### 联网搜索与网页正文读取

本次将搜索接入独立服务，并补充网页正文抓取能力。任务可以先找到来源，再读取正文，结合实际资料组织回答和引用。

搜索不再要求把当前对话模型切换到搜索服务对应的模型。例如，使用 GLM 对话时，也可以通过独立的 DeepSeek 搜索与抓取工具查资料。

可以这样提任务：

> 查找这几个产品的官方说明，读取关键页面，对比差异，并在结论旁附上来源。

搜索负责找线索，抓取负责读正文；需要登录态、网页交互或截图时，继续使用原有浏览器能力。公开网页抓取不用于本机文件、内网或私密链接，禁止联网的任务也不会放开这些工具。

### 普通任务里也能生成图片

除了 Design，具备相应权限与服务配置的普通任务也可以调用生图工具，将图片保存到工作区，再用于报告、页面或其他交付物。

云端账号通过 Stable Cloud 调用搜索、抓取与生图服务，供应商凭据由服务端管理，不需要每位用户额外配置相应的本机 Key。

### 生图失败恢复，更注意避免重复生成

已成功生成但下载中断的图片，会保留任务状态和可恢复的结果信息。重试时优先复用已有生成结果、继续下载；结果不确定时，不直接假定失败并重新付费生成。云端同一请求的重复恢复还会核对请求标识，避免按同一请求重复结算。

**费用说明：** 搜索、网页抓取和生图可能产生独立工具费用，组织最终答案的聊天模型用量另计；服务可用性与费用以当前账号和服务配置为准。

## 07 · 模型连接：按你的使用方式接入

### 新增 ChatGPT 订阅连接

在 **设置 → 模型连接 → ChatGPT 订阅** 完成授权后，可以在普通聊天的模型菜单中选择当前账号提供的 ChatGPT 模型。

模型负责理解和回答，本地文件与工具操作仍通过 Stable 的执行和审批流程完成。每个 Stable 数据目录保存一个账号连接，登录凭据使用系统加密存储。

授权失效或额度不足时，会提示处理当前连接，不会自动改用 API Key 或 Stable Cloud 聊天计费。可用模型和订阅额度由实际账号决定；选择订阅模型也不代表额外的搜索、生图等工具免费。

### 本地 API 连接更容易配置

本地直连模式提供预设与自定义连接，可以填写 API 地址、实际模型 ID 和 Key。Key 加密保存，界面不会回填明文；修改 API 地址时要求重新填写 Key，避免将旧凭据误发给新地址。

保存连接后会设为本地新对话的默认模型，已有对话可自行切换。云端安装模式仍由管理员维护网关模型，不需要在同一页面填写本机 API Key。

### 模型展示与默认选择调整

- 更新 DeepSeek Flash 的显示名称为 **DeepSeek-V4.1-Flash-1017**，便于识别当前产品中的模型标识。
- 对有已知发布时间的模型调整排序，未知发布时间的模型放在后面。
- 补充 GLM-5.3-FlashX 的相关识别和思考强度配置。
- 新默认设置采用 DeepSeek Flash 与高思考强度；此次默认迁移保留已有对话的模型选择，并且不会在每次启动时反复覆盖之后的手动设置。
- 默认模型不可用时给出明确提示，不把“已经保存配置”当成“供应商一定可用”。Design 使用自己的固定任务模型规则。

## 08 · 文件理解与执行过程：多看懂一点，少猜一点

### PPTX 现在可以作为资料读进来

新增 PowerPoint `.pptx` 内容读取，支持按幻灯片顺序提取文字、表格、备注，以及可识别的图表数据和内嵌图片。

你可以上传一份演示文稿，让 Stable 整理重点、比较章节内容，或结合其中的数据继续制作报告。符合格式和大小限制的内嵌图片会作为视觉输入；超出限制时保留可读取路径并说明，避免把“提取到了文件”误当成“模型已经看过图片”。

这是内容读取能力，不等同于完整复现 PowerPoint 的动画、排版和播放效果。

### Excel 兼容性补强

修复部分工作簿因 XML 命名空间差异导致工作表无法识别的问题；对结构缺失或未识别到工作表的文件给出更明确的错误。

内置 Excel 创建、更新也统一进入审批检查。对含宏、图表或透视表等复杂结构的文件，仍保留原有的保真限制，不以不完整另存覆盖原文件。

### Trace，让过程看得明白

工具执行记录集中到 Trace 中，可以展开查看调用输入、执行结果、耗时与状态。主对话更便于阅读，需要追查时再看详细过程。

尤其是：**中间某一步工具失败，不等于整个任务最终失败。** 新版分别展示工具失败次数与任务最终状态，保留过程中的错误记录。

针对 Python 缺失值、字段不匹配、文件依赖、编辑目标不唯一、浏览器元素引用失效等情况，执行器会提供更具体的恢复指引，让模型先核对原因再继续；不会通过隐藏错误或放松检查来制造“已完成”。

## 09 · 长对话与底层执行，也做了调整

### 上下文用量看得见

输入区新增上下文用量入口，展示当前估算用量、容量与占比，并可展开查看消息、系统提示词、工具、技能等分类信息。

长对话会按适配后的模型容量处理自动压缩，在接近配置阈值时整理上下文。识别到可恢复的上下文超限错误时，会尝试压缩后继续，并显示相应状态。

界面数值为 SDK 估算，可能与供应商实际计量不同；这不是“无限上下文”或永久记住全部细节的承诺。

### 减少重复内容和不必要的辅助请求

- 修复首条用户消息重复进入模型上下文的问题。
- 续聊时减少重复发送未变化的规则与技能目录，必要变化仍会重新传入。
- 对相同工具结果、重复截图等进行有条件的上下文去重，保留原始记录及必要证据。
- 明确的简单知识问答跳过额外的需求预判和下一句预测，直接进入主回答。
- 增加空闲时运行环境预加载，减少部分初始化工作进入用户提交后的关键路径；预加载本身不请求模型。

这些变化针对重复工作与调用开销。实际耗时仍取决于任务复杂度、模型、网络与电脑状态，不承诺所有任务都按固定比例加速。

### 执行引擎升级

底层从 Codex Harness 切换为 **Claude Agent SDK 0.3.308**。文件读取与编辑、命令执行、技能、扩展工具和会话生命周期由新的执行链路承接；对话使用哪个模型，仍由实际连接和选择决定。

Windows 命令使用随包提供的 Git Bash，并配合 Node、PowerShell、Python 等运行环境。停止任务时加强相关进程树清理，减少取消后遗留命令继续运行的情况；已经发生的文件写入不会因此自动回滚。

**权限变化需要留意：** 当前本机 Bash 命令经过审批，但不具备 WSL2 的目录和网络隔离。批准后可能访问当前 Windows 账户可访问的文件和网络；只读或禁止联网的任务不开放 Bash。原生文件工具仍执行目录边界检查。

## 10 · 更新与旧数据：把继续使用这件事做好

### 更新下载迁移到 Stable Cloud

新客户端的更新检查与安装文件下载改用 Stable Cloud 的 HTTPS 更新服务。下载安装仍保留用户确认，不强制自动重启应用。

仍使用旧 GitHub 更新源的 1.0.03 用户，可以通过过渡版 **1.0.05** 迁移更新来源。无法访问 GitHub 的电脑，需要手动安装一次已正式发布的完整包；之后由新客户端使用云端更新源。

### 覆盖升级增加备份和检查

- 升级前创建数据备份，在数据库副本上演练迁移并核对历史内容。
- 备份或关键校验失败时阻止继续升级。
- 保留旧程序目录，检查新运行环境；健康检查失败时尝试恢复旧程序。
- 提供手动回退脚本，并校验备份内容。
- 账号密文暂时无法解密时保留原数据，提示重试或重新登录，不直接清空历史。

### 旧对话可以带着可见历史继续

旧 Codex 会话保留原文件和映射，通过可见消息与历史索引为新引擎提供背景。你可以在原来的讨论基础上继续提出任务。

不同引擎的内部思考状态、尚未完成的工具调用无法保证原样续接。升级前请完成或停止当前任务，再正常退出应用。

**从旧版升级时：** 保存工作、退出 Stable，使用正式发布的完整安装包选择原安装目录覆盖安装，避免先卸载再安装。保留自动备份；如需回退，先退出应用，再按安装目录中的回退说明操作。回退会恢复备份时点的会话数据库，新版期间新增消息需要从保留的恢复数据中另行查看。
