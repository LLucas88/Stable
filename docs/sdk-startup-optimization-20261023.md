# SDK 启动优化与实测

## 改动

1. 新增 `claude-runtime-loader.cjs`。桌面加载后空闲 1.5 秒，异步加载 SDK 模块并运行一次 CLI `--version` 预加载可执行代码；有任务运行时延后。进程退出后不保留热 Agent、不共享账号、会话、工具或权限状态，不发送模型请求。版本检查不继承账号凭据、HOME、NODE_OPTIONS；10 秒超时，退出应用时清理自身进程。预加载失败仍允许正常冷启动。
2. `claude-harness.cjs` 使用共享模块加载 Promise，避免在首条消息才承担模块导入；设置 `CLAUDE_CODE_DISABLE_BUNDLED_SKILLS=1`，跳过 Stable 白名单之外的 SDK 自带技能。Stable 的授权技能、插件技能和工具权限保持原逻辑。所用开关语义由已安装 SDK 的 `sdk.d.ts` 说明：不影响插件、`.claude/skills` 和 `.claude/commands`。
3. `createHarnessRunner` 每次只准备一次问鼎 CLI 环境，再复制给可信工具，避免重复扫描旧账号迁移目录。每次任务仍重新准备，不缓存权限或凭据。
4. 增加单调时钟阶段计时：本地准备、SDK 模块加载、桥接、工具、进程启动、初始化完成、首次请求、结果、上下文统计、清理。诊断失败不会中断任务。

未采用 SDK `prewarm/claim` 跨会话复用：该接口固定工具、插件、环境、权限回调等参数，而 Stable 每轮的授权范围和会话目录可能改变。本次没有放宽边界以换取速度，也没有另建削弱能力的聊天执行路径。

## 定位证据

免费真实 SDK 内部日志记录：一次启动加载 18 个 Stable 授权技能及 38 个 SDK 自带技能，commands/agents 阶段约 2.17 秒。Stable 的 `Skill` 授权函数只接受本轮白名单，后 38 个并非可调用能力。

机器总内存约 16 GB，测量期间可用内存曾低至 0.37–0.86 GB，出现 Electron 网络服务重启、首次启动显著变慢。已清理本次卡住的测试进程，未结束原 Stable 或其他应用。较早并发试跑的一次 Bash allow 测试超时；串行复测通过，原失败日志保留。因此不把不同时间的冷启动样本当作固定性能保证。

## 最终真实模型验证

使用原账号的数据副本，真实 `stable:agent:run` 处理器、SDK、桥接和线上 DeepSeek。为减少测试自身内存占用，隐藏窗口且不加载前端页面；从发送处理器开始计时，到回答和状态保存结束。这是实际后端发送流程验收，不是前端交互耗时验收，也不是单次直连接口测试。

| 场景 | 进程启动到 SDK 初始化完成 | Runner 开始到首次请求 | 发送到回答保存完成 |
|---|---:|---:|---:|
| 新对话 1 | 3.417 秒 | 4.250 秒 | 9.373 秒 |
| 新对话 2 | 1.285 秒 | 1.728 秒 | 8.413 秒 |
| 原身份会话副本续聊 | 1.660 秒 | 2.194 秒 | 8.992 秒 |

三轮均明确回答当前模型为 DeepSeek；每轮一个 Runner 调用、一个上游请求。简单聊天的澄清和预测均未额外调用模型。预加载实际执行成功，SDK 模块读取在这三轮中约 0.5–1.1 毫秒。输入仍约 27k–28k tokens，工具及授权技能没有为本测试删减。

上一轮完整耗时为 13.306、11.271、9.639 秒；本轮数值更低，但 UI 是否加载、内存压力和冷缓存状态不同，不作为同条件 A/B 或固定提速百分比。首轮冷启动仍是剩余开销。

网关账单：3 次请求全部 settled，实际 **0.139145 元**，低于本轮获批的 1 元上限。本轮其余验证使用模拟模型，无模型费用。原截图会话消息与账号凭据核对未变。
