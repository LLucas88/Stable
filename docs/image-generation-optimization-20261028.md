# 生图失败与耗时优化：源码及离线验收

## 范围

本轮只修改 D:\stable 客户端源码及 tools/cloud-image 网关覆盖层，使用临时目录、内存 SQLite、模拟供应商接口。未部署、未调用付费模型、未改原账号与历史、未打包、未提交或推送。

## 原因与改动

此前任务总耗时约 653 秒，其中三次成功生图串行占约 542 秒；单张约 179–181 秒。客户端与网关原同步链路都在 180 秒超时附近，提交后断线会留下没有结果的记录。之后的 409 是防重复提交保护，不代表再次生成失败或没有扣费。旧任务没有供应商任务编号，无法凭空恢复结果。

- 新云端协议使用官方异步提交，先保存供应商任务编号，再按原请求查询；每个供应商提交/查询 HTTP 上限 30 秒。新客户端等待总预算 8 分钟、约每 3 秒查询，单次查询在已确认任务后有独立的 30 秒上限；超过预算或取消后仍可用原参数恢复。旧网关同步 200 响应保持兼容，但只有部署新网关后才能获得异步恢复能力。
- 新增 gateway_image_jobs 表保存任务编号和计费快照；并发完成查询仅结算一次。明确 FAIL 释放预留，查询网络失败不释放也不重新生图。通用 stale 清理跳过有任务编号的请求，避免破坏恢复路径。
- stable_image_generate 新增可选 additionalImages（最多附带 1 张），一批最多 2 张。共享队列也限制同会话多个工具调用的并发；独立方案优先分批执行，依赖上张图片的修改保持串行。工具策略升级为 native-bash-v21，使旧 SDK 工具目录在后续运行时刷新；不改写用户消息历史。
- 遇到限流，后续排队降为串行；没有自动补发被限流的生成。供应商实际并发额度尚未在线验证。
- 保留总张数限制、路径保护、下载重试与权限检查。批次在提交前检查参数/路径；部分成功保留已生成图片，不把整批作为新请求重跑。
- 本地结果未知收据阻止更换提示词或输出路径新增生成；排队中的新请求也重新检查。已接受的其他并发图片继续收集结果，不丢弃成功产物。
- 取消排队任务不会提交供应商；取消正在处理的任务仅停止本地等待，不表示供应商取消或退款。重新登录、重建 runner 或重启网关后仍依据原收据恢复。

## 验证

相关客户端回归 **108 项通过**，网关及贯通检查 **25 项通过**；桌面 TypeScript 检查和隔离网关源码 TypeScript 检查通过。所有供应商调用均为模拟，真实费用 0 元。

覆盖：210 秒模拟慢处理、查询网络故障、处理预算耗尽、取消后恢复、网关模块重启、并发重复结算、401 不误解除未决任务保护、未知结果阻止替代生成、批次部分成功、数量限制、权限/目录保护、限流降为串行、旧同步协议兼容。

客户端 → 网关 → 模拟异步供应商 → 下载保存的贯通测试中，每张耗时设为 180 秒，3 张的生成阶段从串行 540 秒变为两波 360 秒，模拟缩短约 **33%**。峰值并发 2，供应商生成提交 3 次、结算 3 次。使用虚拟时钟和测试 PNG；不代表实际图像质量、线上吞吐或完整任务已达到 6 分钟，模型规划和图片检查仍有额外耗时。

网关验证依赖本地既有网关源码快照 `.local/ecs-production/source`，也可将其他已准备的源码路径作为 verify.cjs 参数；不会接触该源码的真实数据库。Windows sandbox 的文件重命名/目录链接限制曾导致测试失败，真实宿主隔离测试通过。虚拟时钟夹具已修正：等待并行请求完成鉴权后再推进时间，避免把测试宿主调度延迟误算成供应商时间。
