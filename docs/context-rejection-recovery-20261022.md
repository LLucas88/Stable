# 上下文超限恢复修复

## 已验证证据

- 原账号日志 `cloud-network.jsonl`：2026-10-22 11:30:59 UTC，网关 `/v1/chat/completions` 返回 HTTP 400。
- 截图具体错误为“请求内容与最大输出长度超过模型上下文限制”。SDK 会话 `12f2f610-fe20-4d56-bbec-1e0b81b75e30` 中，失败前的成功响应记录输入 9,599 + 缓存输入 288,512 = 298,111 token；请求 max_tokens 为 8,192。
- 只读刷新原账号模型列表仍显示 deepseek-flash context_window=1,000,000。不能据此认定真实模型已耗尽 1M，也不能认定是预留输出过大。
- 客户端上次将确定性 HTTP 400 一律终止，未区分 SDK 可以通过压缩恢复的上下文超限。使用真实 SDK、本机模拟网关复现相同中文错误，修复前直接失败，修复后完成原生压缩并继续。

## 修复

- 仅识别明确的上下文长度错误（指定中文错误及标准 context_length_exceeded/maximum context length/prompt is too long）。将其转换为 SDK 可识别的 `invalid_request_error: prompt is too long`，让原生 SDK 压缩会话并继续。
- 原始中文错误留给失败详情；错误恢复状态单独显示“网关拒绝上下文长度，正在自动压缩”，解释界面统计与网关计量可能不同。
- 每个运行的桥最多允许 3 次此类恢复（包含压缩请求本身被拒绝的情况），继续拒绝则停止。没有主动清空历史、删消息或重放已经完成的工具。
- 非上下文 HTTP 400、鉴权错误等仍按之前策略及时失败。

## 验证与限制

- 72 项桥接、执行器、Cloud 代理、失败记录回归通过。
- 3 项真实 SDK 集成通过：上下文超限后压缩并继续、普通 400 只请求一次、工具截图通过 Cloud 格式转换。
- 线上只查询账号和模型目录，没有重新运行用户长报告任务或进行大上下文付费推理。没有取得服务器内部日志，因此网关此次长度判定的内部原因仍未确认；客户端恢复缺陷已有复现和修复证据。
- 保留原账号、历史和已完成脚本；本地改动不推送、不部署。重启运行中的 Stable 后生效。
