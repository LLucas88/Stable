仅分析有效计划 `stable-branch-comparison-20261021-03/campaign/runs/product-1-r001`，不混入前两次环境不完整的计划。产品为 Stable cluade-sdk-bash 1.1.0，原 HEAD `4b09142235ace8c7bfcdaf7a50cdcdbcf841c838`，模型为 DeepSeek-V4.1-Flash-1017 / high。

## 已观察到的问题

该有效轮次为 15 项通过、3 项执行失败、3 项前置阻断；六类等权成功分和质量分均为 85.7143。失败集中在报告工作流：

| 用例 | 实际付费请求 | 工具调用 | 浏览器调用 / 截图 | 直接失败原因 |
| --- | ---: | ---: | ---: | --- |
| report-a | 60 | 70 | 22 / 8 | 请求上限耗尽 |
| report-b | 60 | 82 | 23 / 9 | 请求上限耗尽 |
| resume-b | 60 | 72 | 18 / 6 | 恢复前后合计请求上限耗尽 |

日志的 61 次请求事件包含被拦截的超限尝试，不是 61 次实际付费调用。`resume-b` 后半段显示 `43/42`，属于累计额度控制，不另行重置为 60。三个前置阻断不代表三个独立的产品错误。

1. 三个报告任务均调用了 PATH 上的 `python`，命中 WindowsApps 占位程序并报 Exit code 49；随后部分任务又探测 `python3`、`py` 或其他软件安装目录。产品实际带有可用 Python，但 Claude 执行提示没有提供路径。
2. 报告生成过程中出现未闭合引号、`bad substitution`。长文本及 JavaScript 模板变量经多层 shell 引号传递，导致失败和返工。部分失败可能来自模型生成错误；日志不足以把所有此类错误都认定为 SDK 截断。
3. 页面已经生成之后仍有分散的编辑、滚动和截图，最终未在预算内完成答复。截图数量本身不能证明浪费，仍需真实模型复测验证收尾策略效果；不能通过删除必要验收或放宽请求上限提高分数。
4. 单独的离线检查复现了 `stable_excel` 的兼容性缺陷：合法的带 XML 命名空间前缀的 XLSX 会报 `Cannot read properties of undefined (reading 'sheets')` 或无法解析 `x:Relationships`。三个报告主要使用 Bash，这个缺陷不能被说成三项报告耗尽请求的唯一根因。

## 修改

- **Excel 兼容性**：按 namespace URI 在内存中规范化已知 SpreadsheetML、包关系及内容类型名称，支持不同关系属性前缀。使用 XML 解析器处理，不用字符串全局替换破坏单元格文本；处理默认命名空间冲突和局部重绑定，拒绝 DTD/实体声明。普通无前缀工作簿保留快速路径。读取和另存共用兼容处理，原文件不写回，缺失工作表返回明确错误。
- **运行时发现**：只向具备 Bash 权限的任务提供经文件存在性检查的内置 Python 绝对路径及 `STABLE_BUNDLED_PYTHON`，包括开发与打包布局。明确使用 `-I -X utf8`，不猜测其他软件目录；不存在时提供明确备用工具说明。只读、禁网和纯文本任务不因此获得 Bash 能力。更新工具策略版本，避免恢复旧会话时继续沿用旧执行提示。
- **Bash 失败恢复**：对实际引号/展开错误附加提示，要求核对已有文件，使用原生 Write/Edit 保存脚本后再执行；不自动改写或重试命令，不绕过审批，不假设失败操作已经回滚。
- **报告收尾**：提示先交付必需产物、完成数据和交互验收，再集中修复观察到的问题；预算有限时预留核验及最终答复空间，保留未验收清单。没有放宽工具权限、60 次请求限制或评分规则。
