# 模型身份与简单聊天重复调用修复

## 原因与修复

实际路由为 `deepseek-flash`，但 Claude SDK 使用 `claude-sonnet-4-6[1m]` 作为协议/上下文兼容标识，并在系统提示及用户消息的独立 `<system-reminder>` 块里注入 Claude/Sonnet 身份与知识截止日期。桥接层此前原样转发，导致模型重复错误身份。

新增 `desktop/services/model-identity.cjs`，在转发前替换完整的 SDK 身份块，注入当前路由的显示名称和模型 ID。保留兼容标识用于 SDK 能力配置，不改上游模型路由；不改用户引用、工具输出、旧回答及持久化历史。模型切换时按当前路由重新生成身份说明；不猜测未配置的知识截止日期。

`clarification.cjs` 使用全消息匹配识别问候、身份、能力介绍和致谢；这些消息不再调用前置澄清模型。附带文件、引用、额外操作要求及待回答澄清仍按原流程处理。`message-predictions.cjs` 对同类简单聊天不再调用回答后的预测模型。普通知识问答和复杂任务不在此确定性快捷规则范围内。

## 验证

- 99 项身份桥接、澄清、消息预测、主发送 IPC 和 Harness 回归测试通过。
- 真实 SDK + 本机模拟上游：新建和续接两轮均只有一个请求；转发内容中的 SDK 错误身份已消失。此项不代表真实模型验收。
- 真实 DeepSeek 验收通过 Stable 的 `stable:agent:run` 发送处理器、Claude SDK、本地桥接及线上网关。使用原账号的数据副本；两轮新对话及截图会话的副本续聊均正确回答 DeepSeek，每轮只有一个 Runner 调用及一个上游请求。显式调用预测入口均返回 null，无额外请求。
- 原会话副本的回答主动更正了此前的 Claude/Sonnet 错误。验收脚本最初用全回答正则误拒绝了这段历史引用；已修正为检查当前首行身份，并独立复核保存的三轮结果，未为此重跑付费调用。原始失败记录保留。
- 原会话消息及账号凭据逐项/哈希核对未改变。
