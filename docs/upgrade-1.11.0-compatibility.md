# v1.11.0 升级兼容与回退

## 已实现

- 完整安装包和轻量更新包都携带 Git for Windows 2.56.0.windows.3 的 Git Bash。Claude SDK 优先使用包内 Bash，并将包内 Git 工具加入子进程 PATH；不依赖目标电脑预装 Git。来源、归档 SHA-256 和许可证随运行时保存；可用 `npm run runtime:git` 重建。
- 手动运行完整 Setup 覆盖旧版时也使用目录切换流程。升级前创建数据备份，在数据库副本上执行迁移并比对原历史内容。备份失败或历史内容发生变化时阻止升级。模型路由编号的正常迁移不视为历史丢失。
- 数据备份位于原数据目录的同级目录，例如 `%APPDATA%\stable-desktop-upgrade-backups\时间-随机后缀`。备份包含数据库一致性快照、账号密文与 Windows 加密元数据、工作区和旧会话文件；缓存不复制，符号链接记录目标但不跟随复制外部文件。
- 首次启动新版会为当前 Windows 用户再次执行备份与迁移检查；数据库打开失败时恢复升级前的关键数据。备份必须通过逐文件 SHA-256 校验才可用于恢复。
- 安装器保留 `安装目录.__stable_previous_1.11.0`，重复升级使用不同后缀，不覆盖此前备份。新版本启动不会自动删除旧程序或失败现场。
- 新版健康检查实际启动 Git Bash、Node、PowerShell、Claude 二进制，并加载 Claude SDK。失败时恢复旧程序目录。安装器不会强行结束未安全退出的 Stable。
- 程序目录切换遇到短暂文件占用时有限重试；持续占用仍停止并保留旧程序。完整演练发现并修复了新版目录切换瞬时失败的问题，新增真实文件锁测试覆盖成功升级、健康检查失败回退及持续锁定的安全停止。
- 旧 Codex 原生线程不交给 Claude 强行 resume。保留原文件和映射，将完整可见消息导出为按会话隔离的只读历史索引；新引擎获得近期消息、最初用户要求以及完整历史索引路径。旧引擎内部推理、尚未完成的工具调用不宣称可以跨引擎恢复。
- 账号密文解密失败时保留原数据并显示重试/重新登录提示，不再自动删除。服务端明确返回 401 的已失效登录仍需重新登录；不会清空历史。

## 手动回退

升级其他电脑时，先保存工作并退出 Stable，再运行完整 Setup，选择原安装目录覆盖升级。不要先卸载旧版或改装到另一目录；程序备份与下述回退路径按原安装目录的覆盖升级流程建立。

1. 保存工作并退出 Stable。
2. 在安装目录运行 `Rollback-Stable.ps1`，例如：

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File "你的安装目录\Rollback-Stable.ps1"
   ```

3. 脚本先校验备份并恢复数据库、账号密文和匹配的加密元数据，再恢复旧程序目录。新版程序移入独立的失败目录；被替换的数据保留在 `upgrade-recovery-*`，升级后新生成的工作区文件不会被删除。

回退会恢复备份时点的会话数据库；回退之后要查看新版期间新增的消息，应保留恢复目录中的新版数据库。备份不会自动清理。

如果文件占用等原因导致恢复中断，程序会保留 `stable-upgrade-restore-pending.json` 和恢复目录，并阻止正常启动。解决占用后重新运行回退脚本；不要删除标记来绕过恢复检查。

## 适用边界

其他电脑的具体旧版本、Windows 用户和安装位置尚未知。以上验证覆盖本地找到的旧版本；不宣称所有历史版本均已验收。应在其中一台旧电脑先覆盖升级，确认账号、历史和旧会话续接后再扩大范围。保留该电脑原数据目录与自动备份，不要把本机加密凭据复制到另一台电脑作为登录方式。

本次只生成本地安装包，不推送 Git、不发布更新、不改线上网关部署。安装包未配置发行者代码签名。
