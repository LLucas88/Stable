# 提问卡片与信息充分性判断

适用于 Codex Harness 的交互式任务发送入口。

## 当前行为

- 当前策略覆盖旧全局规则中“每个任务先问”和 95% 的频率要求，保留其他全局规则，不改写用户的 AGENTS.md。旧 `stable:clarification=always/auto` 注释不再控制提问频率。
- 简单问候、自我介绍、能力介绍和明确问答直接处理。复杂任务先进行无工具的信息充分性判断：仅当模型自评信心低于 0.9，存在会影响结果的具体缺口，且返回有效问题及两条路线时才出卡片。0.9 是模型自评阈值，不是经过统计校准的成功率。
- 可从已提供文件或仓库自行核实的信息交给执行阶段读取，不因预检尚未读文件而问用户。无效的评估输出不制造强制确认；交给执行模型依据上下文继续判断。
- 模型梳理一个关键决策，给两条具体、互斥的路线和各自影响，第一条为推荐路线。第三项允许用户自由补充，并展示模型提供的辅助提示。
- 卡片首次显示时启动 20 秒倒计时，显示在发送按钮中。未操作时提交推荐路线。点击卡片任意位置、键盘进入卡片或输入都会永久取消当前问题的倒计时，等待手动发送。跳过、关闭均按推荐路线继续。
- 倒计时起点与取消状态由主进程保存在本地数据库，切换后返回不会重启已取消的倒计时。应用关闭或卡片未挂载时不执行自动提交；未交互的卡片再次显示且原倒计时已结束时，会选择推荐路线继续。
- 主进程校验问题 ID、选项、超时时间与取消状态。重复超时、旧问题和非法选项不会执行。自动选择注明“模型自主选择”，不是用户确认事实或授予权限；既有权限审批保持独立。
- 选择后恢复原任务及附件、资源引用。用户可从普通输入框继续补充。原附件仍须重新核验；模型不得编造缺失文件或数据。用户回复“取消”结束待澄清任务；“新任务：”开始独立请求。
- 等待补充时暂停后续消息队列；补充回答先于无关排队任务，完成后恢复队列。失败时不自动重做操作。

## 运行时协议

执行中提问在最终回答第一行写 `[[STABLE_WAITING_FOR_INPUT]]`，后面返回包含 `question`、`hint`、`options` 的 JSON。标记和 JSON 不显示在流式正文里，交付检查保留结构化选项，等待补充时不自动重试文件生成。

原生 requestUserInput 仍通过中断转入提问流程，禁止伪造空 answers。无结构的旧问题会让模型整理为两条路线；若格式无效则提供保守默认路线（按现有证据继续，或先整理方案与缺口）。

## 本地启动与验证

在 PowerShell 中：

```powershell
Set-Location E:\Stable
npm run test:clarification
npm run typecheck
npm run build
npm start
```

若已经运行旧版本，先自行退出旧窗口再启动。测试使用本地模拟模型响应及打包 Codex 运行时，不消耗外部模型调用。界面测试使用独立数据目录和隐藏 Electron 窗口，不操作当前客户端。

测试覆盖：90% 边界、简单问答、原任务和附件恢复、真实 IPC 验证、超时与点击竞争、数据库重开、重复提交、自由回答、跳过和关闭、窄屏和完整聊天页面、消息队列暂停与恢复。

人工验收示例：

1. 发送“你好你叫什么，你能帮我做哪些事”，应直接回答。
2. 发送有实质意图缺口的任务，检查模型问题与两条路线是否有助于选择。提问由模型判断，不保证任意模糊措辞都出卡片。
3. 卡片不操作 20 秒，应按推荐路线继续；刷新历史可见“模型自主选择”。
4. 点击卡片标题后等待超过 20 秒，应保持等待；选择第二项或填写第三项再发送。
5. 点击跳过或关闭，应由模型选择推荐路线继续原任务。
