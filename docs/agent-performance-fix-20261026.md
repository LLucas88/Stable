# Agent 上下文、简单问答与 Design 模型选择修复验收

验收日期：2026-10-26。工作区：`D:\stable` 当前源码；本轮真实调用费用上限 5 元。没有推送、部署、制作安装包或替换正在运行的原 Stable。

## 修复内容

1. **首轮去重**：用户消息入库后，构造历史时按该条消息 ID 排除，再计算历史预算。当前请求只出现一次；不按文本删重，历史中合法的重复提问仍保留，数据库内容不删除。
2. **续聊规则去重**：拆分稳定的规则/技能目录与当前回合请求。恢复 SDK 会话时只发送当前回合；规则指纹变化或旧指针没有指纹时补发一次完整规则。权限、模型、工作区等原有会话隔离条件保留，新 SDK 会话仍接收完整初始上下文。
3. **简单问答减少调用**：明确的短知识问答、定义和简单算式跳过需求预判与下一句自动预测，主回答仍由模型生成。带资源、混合操作、待澄清/审批等情况继续走原逻辑。原有预测功能开关和复杂任务逻辑保留；预测缓存版本更新。
4. **Design 的对话模型显式化**：显示“对话模型”选择器，说明其与 GLM-image 的职责不同。新建 Design 优先选择目录中已配置凭据的 GLM-5.3-Flash；不可用时保留正常默认模型并显式展示。既有会话和全局默认不自动迁移。

“已配置凭据”不等于供应商余额足够，不做隐式付费探测或自动切换付费供应商。

## Design HTTP 402 根因

只读检查发现，原数据中两个 Design 会话的生图参数是 `glm-image`，但会话对话模型仍是 `legacy-default-model`，映射为 `deepseek-flash`。前端 CSS 隐藏了普通对话模型选择器，仅展示 GLM-image。发送链路先解析会话对话模型，执行理解需求/调用工具，再由 `stable_image_generate` 调用智谱图像接口。

因此 GLM-image 没有绑定 DeepSeek；此次故障发生在前置的 DeepSeek 对话调用阶段。原网络日志在 03:30:00Z 和 03:32:41Z 记录 `/v1/chat/completions` 返回 402。GLM-image 的图像接口仍独立使用智谱凭据。此前已显示的供应商余额不足提示没有被改成模糊的“执行失败”。

修复后旧 Design 会话可以明确选择 GLM-5.3-Flash 再继续队列；切换模型不会改变 GLM-image 的生图参数。本轮验证了真实 IPC 路由和隐藏窗口的选择操作，没有重新付费生成图片，也没有改写原会话选择。

## 费用、完整性与未解决的性能问题

网关只读用量汇总与本地记录完全匹配：**23 次请求、1,182,538 输入 token、5,097 输出 token，全部结算，0 异常**。实际费用 **0.698253 元**；按无缓存价格计算的保守上限 0.960302 元，均低于 5 元。没有额外图像生成调用。

基线费用为 0.615443 元，本次没有更便宜。总输入从 1,549,085 降到 1,182,538，但缓存命中 token 从 1,120,256 降到 459,776，命中比例约 72.3%→38.9%。缓存复用受前缀变化、时效和供应商状态影响，本轮不足以确认长期费用趋势。不能用输入量降低直接宣称账单降低。

测试前后原数据的 1,190 条消息内容校验一致，凭据文件校验一致。测试创建的会话、脚本、HTML 均位于数据副本。本轮没有自动改写旧 Design 或全局模型设置。

后续可优化点：普通简单问答仍带约 26.9k 输入 token；SDK 原生初始化约 1.3–4.4 秒；上游响应等待波动明显；复杂任务仍有预判和脚本修复成本。本轮没有为追求速度撤销权限检查，也没有扩大到持久进程池或更换模型策略。
