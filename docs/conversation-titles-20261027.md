# 自动任务命名优化（2026-10-27）

## 核对结果

本机 Codex 26.1021.3705.0 打包源码使用临时标题加异步元数据命名：标题描述主要动作、具体对象、用户语言，保留工单等标识，限制长度；写回时检查预期旧标题，避免覆盖手动名称。这是本地打包代码证据，不代表完整服务端实现。实验路径存在 24/36 字符限制及周期性更新，本次不照搬周期性模型调用。

Stable 原逻辑直接截取首条消息前 32 字，容易保留客套话、截断交付目标，也可能覆盖首条消息前设置的手动名称。

## 实现

- 先用本地规则生成短标题，最长 24 个 Unicode 字符；短问题和简单聊天不增加命名调用。
- 长任务首次成功完成后异步生成一次标题，中文目标 8–16 字，保留对象、动作和版本信息。只发送有界任务文本，不携带附件正文、历史、技能或工具。
- 使用原任务模型，最多一次请求、512 输出 token、15 秒超时；不阻塞任务完成。新任务开始取消尚未完成的命名；失败保留临时标题，不重试。
- 新增状态列，旧会话保留原标题；手动改名、删除首条消息或切换模型后拒绝过期结果。仅更新标题，不改消息或更新时间。

## 验证与界限

68 项相关离线回归通过；3 项真实 SDK 对模拟供应商的回归通过（命名限一次请求、输出上限和无工具、失败不重试）。类型检查和前端构建通过。数据库测试使用临时副本；无付费模型调用。

本地样例：`帮我修复 SDK 初始化速度` → `修复 SDK 初始化速度`；`请问你是什么模型？` → `你是什么模型`。长报告任务在模拟返回 `生成经营分析报告` 时已验证安全写回；该模拟只证明流程，不证明真实模型的标题质量或线上耗时。

复杂任务的异步命名会额外产生最多一次模型请求及相应 token 费用，简单聊天不增加此费用。没有打包、推送，也没有批量重命名旧历史。
