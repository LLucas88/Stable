## 后台通知直接审批（新增）

完全退出测试版并用同一启动脚本重新启动，以加载主进程修改。

1. 任务出现审批卡时先不处理，将 Stable 最小化，或关闭到托盘（保留后台运行）。
2. 右下角通知应显示任务名称、脱敏后的授权原因/操作摘要，以及“允许一次／本次对话允许／拒绝”。不支持对话授权的执行器只展示另外两个按钮。
3. 点“允许一次”：只处理该次审批，任务继续，通知撤销，对话里审批状态同步。
4. 在另一审批点“拒绝”：该操作不被执行；模型可解释或选择其他方法。
5. 点“本次对话允许”：使用现有对话授权规则，按原审批类别和范围生效，不是无限制授权所有后续操作。
6. 关闭通知：任务仍等待，不默认允许也不默认拒绝。点正文则打开对应任务的完整审批。
7. 同一审批先在对话里处理，再点残留通知：不得执行第二次。停止任务后，通知应撤销，旧按钮不得影响新任务。
8. 窗口保持前台时，仍在对话内审批；之后最小化才展示原生审批通知，同一请求不因反复最小化而反复弹出。

授权摘要超过通知空间会截断，完整内容通过点击正文查看。样式随 Windows 系统通知主题展示。实际系统弹窗与按钮回调仍需手工验收；自动化覆盖状态和事件逻辑。
