# 多智能体任务与交接设计

用于用户明确需要持续多智能体协作的工作流。小任务保持单智能体即可。

1. 按实际任务确定职责、依赖和验收条件，避免多个执行者同时修改相同文件。
2. 任务状态可采用待分配、执行中、审查、完成或失败；记录实际状态和负责人。
3. 每次交接带上目标、已有结果、产物路径、验证方式、已知限制和下一步。
4. 根据本轮实际暴露的 Codex 协作工具派发与等待。没有对应工具时只交付设计方案，不能把文字中的派发当成实际执行。
5. 模型与人数遵循用户要求及可用配置。审查需检查实际产物与验收证据，不能只复述执行者的完成声明。

可按需要读取 `references/task-lifecycle.md`、`references/communication.md`、`references/patterns.md`。其中 sessions_*、cron、SOUL.md 和固定模型名属于原宿主示例，不是 Stable 的可执行命令或全局配置要求。不得因此自动开新会话、改变模型或建立定时任务。
