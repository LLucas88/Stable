# 工作经验与纠错日志

遇到与当前任务有关的错误、用户纠正、知识缺口或更有效的操作方式时，记录可复用的经验。先验证原因，区分用户提出的解释与已证实结论。

- 只在当前用户工作区的 `.learnings/` 下追加日志，已有文件不覆盖。
- 工具或执行错误写入 `ERRORS.md`，纠正与经验写入 `LEARNINGS.md`，用户提出但当前缺失的功能写入 `FEATURE_REQUESTS.md`。
- 记录日期、简短标识、触发场景、可复现证据、解决办法及适用边界。重复条目更新证据或关联已有编号。
- 只保留必要摘要，不记录凭据、令牌或完整会话。
- 后续相关工作可读取相应日志。持久化的范围是这个工作区，不承诺自动跨会话注入或跨项目共享。

日志示例和格式可参照 `references/examples.md` 与 `assets/LEARNINGS.md`。原包的 hooks、OpenClaw 集成脚本与人格配置不属于迁移后的运行路径。需要把经验提升为项目规则时，先给出有证据的具体修改，再遵循用户对项目规则的授权范围。
